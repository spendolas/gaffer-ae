# Gaffer landing page — design

Status: the page is built and has had its final whole-branch review locally; the look is baked into the config defaults. The dev tweak panel and the presets still exist pending the Task 8 cleanup, and deploy (Pages workflow, `install.md`, DNS) is still pending.

## Purpose

A showcase for Gaffer with one conversion: getting visitors to paste an install prompt into Claude Code.

- **Audience:** After Effects users curious about bringing AI into their workflow. Craft-first, little jargon. Not an AI-tooling audience.
- **Success:** a visitor sees what Gaffer-made motion looks like, understands it needs Claude Code, and copies the install prompt.
- **Not goals:** waitlist, live pricing, blog, analytics, marketing copy sections.
- **Constraint:** Gaffer is Claude-only. The page states "Requires Claude Code" and does not help visitors who lack it.

## Experience

One locked, fullscreen page. No scrolling.

1. **Stage:** dark background filled by an infinite, draggable, domed grid of looping clips, laid out as rows of tiles that keep each clip's own shape (wide clips get wide tiles), with rows that can shift relative to each other. Built on the `no-gl-grid` technique (plain DOM, one `matrix3d` per card, modulo wrap, pincushion warp, cursor bulge, flashlight mask). No WebGL, no dependencies, no build step.
2. **Cards:** cards have no hover state; the cursor bulge on the dome is the only pointer reaction. No click behaviour, no captions, no flip panel, no lightbox.
3. **Dock:** a pill pinned bottom-centre, above the grid, always visible. Contains the visible install prompt text (no wordmark) and a group of two buttons: the primary "Install with Claude" link and the secondary Copy button (labels set in the config's copy group, "Install with Claude" and "Copy prompt" to start). Below it, a plain-text "Requires Claude Code" note (no links). There is no "How it works" link at this stage.
4. **Headline:** a large centred `<h1>` over the grid in two lines, using the Gaffer panel's wording: a title ("Gaffer", large display type, sized by the headline settings) and a smaller, muted subtitle ("your AI crew in After Effects"), each with its own settings. The two-line block sits above the stage and fader and below the toast, in one bottom-anchored column with the dock (`.bottom-stack`): the headline above, the dock below, `headline.dockGap` px between them (`headline.dockGapCompact` at 600px and below). The two reflow together as the dock grows (the note wrapping, the failure reveal), so they never overlap, and the whole column stays pinned to the bottom of the viewport, takes no pointer events (the grid drags straight through it), balances each line's wrapping, and scales with the viewport width (vw units, a larger size at 600px and below; the title is also capped by the viewport height, and the subtitle by its own height cap). Both lines force font ligatures on by default (browsers otherwise drop them at non-zero tracking). It is plain markup, so it shows without JavaScript, with the real defaults: the config defaults are inlined as boot variables in the head.
5. **Fader:** a big, soft ellipse in the stage colour pinned to the bottom centre of the viewport, behind the headline and the dock and above the grid, so the text reads over the moving clips while the grid fades out around it. A radial gradient with an eased (smoothstep) alpha, not a CSS blur, so it costs no raster time while the grid animates; softness is the solid fraction of the ellipse before it feathers out. It takes no pointer events (the mouse and drags go to the grid), and it is a static decorative element, shown without JavaScript with the inlined boot variables. The fader has two modes, switched by `fader.mode` (default `ellipse`): the **ellipse** overlay above, and the **row fade**, which dims each tile in proportion to the share of its height inside the headline band or the dock band, with a short feather beyond the band; `both` applies the two together and `off` neither. In `rows` and `off` the ellipse is hidden.
6. **Touch:** drag only. No hover. The flashlight rests at the centre at double radius as a soft vignette. The dock uses its compact variant, which is width-based (600px and below): the prompt text is hidden and the pill holds the buttons, including the app link. Only `data-app="none"` (the platform check, see Install flow) hides the app link and makes Copy the single primary button, labelled "Copy install prompt" because the prompt text is hidden there; it still copies the full prompt.

Layout reference: a rough Figma scaffold in the team's Plugin Dev file, Gaffer page, section "Gaffer Landing"; no longer the source of truth. The look is now decided in the browser, see "Visual design".

## Install flow

The CTA copies a prompt; the visitor pastes it into Claude Code (CLI or desktop Code tab).

- **Prompt (single constant in the source):** `Install Gaffer by following https://gafferae.com/install.md`
- The full prompt text is visible next to the button, so nothing pasted is hidden. The visitor can open `install.md` at the same URL to read what the prompt follows.
- **`install.md`** is a pinned, deterministic doc served raw from the site. It follows the README's existing install steps (Mac and Windows), uses the latest GitHub Release assets (no hard-coded version), and ends with a verification step. Written so an agent can execute it without interpretation. Content is drafted during implementation from README + `scripts/install-*`.
- Copy uses `navigator.clipboard.writeText`; fallback selects the visible prompt text and `execCommand("copy")`.
- **Confirmation:** a successful copy must be confirmed visibly, as a toast (shown ~2s, auto-dismissing) and announced through an `aria-live` region. The decided confirmation is the success toast plus the animated copy-to-check icon on the Copy button (see Dock behaviour); there is no separate dock state. If the copy fails (clipboard blocked and the fallback fails), the toast says so and the prompt text stays selected so the visitor can copy it by hand.
- **Primary action: open in the Claude app.** "Install with Claude" is a plain anchor in the static markup (it works without JS) to `claude://code/new?q=<url-encoded prompt>`, built by `desktopLink` in `dock.js` from the same prompt constant. It opens the Claude desktop app on the Code tab with the install prompt prefilled; the prompt is never sent automatically, the visitor presses Enter. `q` is capped at 5,000 characters by Anthropic and there are no cwd or repo parameters. This is the filled, primary button. Its label is `copy.linkDesktop`. The caveat has one wording, used for both the tooltip (`title`) and an accessible description: a static visually-hidden element (`dock-hint-app`, with the `hidden` attribute so it is not read on its own when the link is display:none on phones) sits in `#dock` outside the pill and the anchor points at it through `aria-describedby`, because a `title` alone is not announced on keyboard focus or touch; `aria-describedby` still resolves a hidden element. The visible label stays the accessible name (no `aria-label`). Without JS it is underlined in a literal colour so it reads as a link. There is no auto-launch or redirect. **Desktop only:** the button is shown on desktop platforms (macOS, Windows, Linux) only, decided by a platform check in JS (`isDesktopPlatform` in `dock.js`: `navigator.userAgentData` when present, else `platform`/`userAgent`; Android, iOS, iPadOS-as-`MacIntel` with touch, an ARM Linux platform on a touch screen (Android Firefox in "desktop site" mode), and ChromeOS count as not desktop; an environment that reports nothing at all counts as desktop). On a non-desktop platform `mountDock` sets `data-app="none"` on `#dock`, which hides the link and turns Copy into the single filled button. The check does not depend on viewport width, and without JS the link stays visible. This is an honest platform guess, not an installed-app check: a desktop visitor without the app who clicks it sees nothing happen or a browser prompt, and Copy is the dependable path.
- **Secondary action: Install with CLI.** Between the app link and Copy, a secondary button (same fill and hover as Copy, Lucide `terminal` icon plus the label `copy.linkCli`, default 'Install with CLI') is a plain anchor to `claude-cli://open?q=<url-encoded prompt>`, built by `cliLink` in `dock.js`. It opens a terminal window with Claude Code and the prompt prefilled, not sent until the visitor presses Enter (documented at code.claude.com/docs/en/deep-links; `q` only, no `cwd` or `repo`). The CLI registers that handler itself after the first prompt of an interactive session, so for a CLI user who has never run it the link does nothing, like the desktop link without the app; the tooltip and the hidden description (`dock-hint-cli`) say so, and Copy stays the dependable path. It is hidden together with the app link when `data-app="none"` (a phone has no CLI) and is icon-only, named through `aria-label`, in the compact variant.
- **Secondary action: Copy.** The Copy button follows the app link in the same group, as an icon-only secondary button (the Lucide `copy` icon, inline SVG added by JS, about 18px, in the text colour), and stays the dependable path: it works on every device and browser, including where the `claude://` link has no handler. The secondary button has no border; its fill at rest is none (`color.secondaryFill`, default `transparent`) and `color.secondaryHover` (default `rgba(255, 255, 255, 0.125)`) on hover, plain colours layered over the dock pill. Both buttons share one padding and line height, so they render at identical height; the icon-only button has equal padding all round, a circle at the pill radius. The accessible name and tooltip of the icon-only button come from the wording config (`copy.button`, default 'Copy prompt') through `aria-label` and a matching `title`, updated live when the wording is edited. The icon is Lucide's, ISC-licensed; its licence and copyright notice are in `site/LICENSE-lucide.txt`.
- **Button group.** The two buttons sit in one `.dock-ctas` container (a plain `div`, no role, since a two-button group needs no extra announcement) with their own spacing: `dock.ctaGap` (px between the buttons, default 4, 0..24) and `dock.ctaPadding` (px of padding around the group inside the pill, default 0, 0..16), both emitted as px CSS variables; the group padding is zeroed in the compact variant so the single button stays centred. The keyboard focus ring is a 2px outline with a 1px offset so it stays clear of the neighbouring button at the default gap. `dock.gap` (prompt to group) and `dock.padding` (the pill's own) are unchanged.

## Content and media pipeline

Clips are the product of the page and must be addable without touching code.

- **Source of truth:** `site/media/<slug>.mp4` (H.264), optionally with `site/media/<slug>.hevc.mp4` (its HEVC companion), `site/media/<slug>.jpg` (a hand-made poster) and `<slug>.webm`.
- **Posters:** if a clip has no hand-made poster, the build takes its first frame with `ffmpeg` and writes it to `site/media/_generated/<slug>.jpg` (gitignored, never committed). A hand-made poster always wins over a generated one. The build never fails because a poster is missing; it fails only if a video cannot be read or `ffmpeg` is unavailable. The deploy runner has `ffmpeg`; locally it comes from `brew install ffmpeg`.
- **Manifest:** `site/items.json` is generated, never hand-edited: an array of `{ id, video, poster, hevc?, webm?, width, height }` sorted by filename. `hevc` is present when `<slug>.hevc.mp4` exists; a `.hevc.mp4` file is never an item of its own, and a non-URL-safe name is copied to `_generated/` like `video`. Generated by `scripts/site/build-manifest.mjs` (Node, no dependencies), run by CI on deploy and by hand for local preview. The same step creates any missing posters.
- **`scripts/site/add-sample.sh [--square] <input.mov|.gif|.mp4> [slug]`:** one ffmpeg recipe, so every clip is uniform. Without a slug the clip gets the next serial name (`clip-01`, `clip-02`, ...), so the public page carries no source names; `docs/site-clips.md` maps each serial to its source export and the script appends a row. Height = the source height after the crop, capped at 800px (never upscaled), width from the aspect rounded to an even number, with the aspect clamped to 0.5..2.4 (a centre crop removes only what lies beyond the clamp); `--square` centre-crops to a square with the same cap. Writes `<slug>.mp4` (H.264, CRF 20, `-tune animation`, preset slow) and `<slug>.hevc.mp4` (libx265, CRF 23, preset slow, `hvc1` tag for Safari); both yuv420p, BT.709 tagged (untagged sources read as BT.601, matching After Effects' untagged ProRes), source frame rate kept, no audio, faststart. The CRFs were measured on the flat clips: the lowest-size settings with no visible banding or blocks, and equal quality between the two codecs. Without libx265 it writes the H.264 file only and says so. Warns above ~6 MB per file. It makes no poster; the build generates one from the first frame (see above). Requires `ffmpeg` (`brew install ffmpeg`). Does not commit; prints what to `git add`.
- **Source masters (ProRes, large GIFs)** stay out of git (GitHub rejects files over 100 MB). Only compressed outputs live in `site/media/`.
- **Adding a piece** = run the script (or drop in your own mp4, with a poster if you want a specific frame), commit, push. No code edits.

## Grid behaviour

- **Row rings.** Every row has the same height, the card size rule (`min(grid.tile, viewportWidth / columns - gap)`, never below 40px; `columns` is `grid.columnsCompact` (default 2) on phones, viewport width up to and including 600px, the same breakpoint as the compact dock, and `grid.columns` above it, so a 390px phone gets about two tiles across instead of four tiny ones; crossing 600px re-tiles like any other geometry change). A tile is that tall and `round(height x aspect)` wide: in native mode the aspect is the clip's own `width / height` from the manifest, clamped to `grid.aspectMin..grid.aspectMax`; in square mode every tile is 1:1. Media fill the tile with `object-fit: cover`, so clamped clips are cropped. Tiles in a row are `grid.gap` apart, rows are `grid.rowGap` apart.
- Rows are identified by their **world index** on the infinite vertical axis. Row `w` sits at `y = w * (height + rowGap) - panY`, and the `R = ceil(vh / (height + rowGap)) + 2` rows whose `y` falls in the centred window `[-R*py/2, R*py/2)` are alive; a row is created and destroyed a whole row beyond the viewport, from a pool of cards. Each row owns a **ring** of tiles that wraps horizontally: the row's own seeded shuffle of all clips (seed from `grid.seed` and the world row), at most 12 distinct clips per row (a different subset per row when there are more), in at least two shuffled passes and more if the screen is wider than that, so even 3 clips fill a row. The same clip never sits next to itself in a row, across the ring's seam included, when there are two or more. Zero clips render an empty stage; one clip repeats. Tiles never change clip while panning horizontally; more than 12 clips show up across different rows, and Reshuffle (a new seed) deals a new order. Nothing stops the same clip from appearing directly above another.
- **Resize stability.** A row's content depends only on its world index, never on the number of rows `R` or on the viewport width, and its horizontal wrap window is anchored to the viewport edge. So a resize that changes `R` adds or removes rows at the top and bottom edges only, a width change just rescales the tiles (the pan keeps its place, every visible tile moves by the scale factor and keeps its clip), and the only deliberate rebuild is the 600 px phone breakpoint, where the column count and so the tile size change. This is replayed in `scripts/site/rows.test.mjs`, which also runs the old slot-based model through the same sweeps to show it jumped.
- **Row shift.** A static stagger, `grid.rowShift` (0..1) times the row's average tile width, scaled per row by `grid.shiftMode`: `alternate` shifts odd rows, `step` shifts each row one more than the last, `random` a seeded amount per row. The pattern follows the infinite grid's world row, not the repeating row slot, so it continues unbroken across the vertical wrap; a row's shift changes only while it is off-screen. A parallax, `grid.rowSpeed` (0..0.5): each row pans horizontally at its own seeded speed between `1 - rowSpeed` and `1 + rowSpeed` of the drag (0 keeps all rows together); vertical pan is shared.
- **Idle drift.** `motion.idle` (px/s, default 12, 0 to 120; 0 and reduced motion turn it off) adds a steady sideways offset to the pan before each row's parallax scale (`rowSpeed`), so an untouched grid keeps the row-by-row drift a scroll gives. `motion.idleMode` (same, alternate, random; default alternate) picks each row's direction from its world row. It does not feed the speed signal, so the bow does not react to it. It makes every frame re-warp the near cards, so the page no longer sleeps when idle.
- **Adaptive frame rate.** The grid steps at the display refresh while the user interacts (drag, fling, scroll), and at about 30 fps for pure idle drift. A governor watches interactive frame intervals: on a ~120 Hz display that sustains under ~87 fps it locks the grid to 60, and if frames stay over 24 ms it cuts the playing videos from 12 to 6. Both decisions are one-way for the session, so the rate never flickers.
- **Dock note.** `copy.note` is split on the bullet (\u2022) into one span per part with bullet spans between; on phones the parts stack and the bullets hide. `dock.notePadding` (px, default 8, 0 to 40) pads the note and `dock.noteGap` (px, default 6, 0 to 40) is the space between each part and the bullet, which sits above the pill's glass shadow.
- **Fader grain.** The fader is one `<canvas>` covering the viewport, drawn by `site/js/fader.js`: the ellipse (centre `fader.offset` px above the bottom edge, `fader.width` x `fader.height` px, phone values at 600 px and below), its colour (`color.fader`), an eased falloff after `fader.softness`, and noise (`fader.grain`, levels of 8-bit alpha, default 1.5, 0 to 8) added to the alpha BEFORE it is rounded, so the average is exact and the soft edge does not band (Safari does not dither CSS gradients). It replaced a CSS gradient plus two masked noise layers: one layer for the compositor instead of three, and a procedural fill instead of a bitmap because the ellipse is tuned live and a fixed bitmap stretched to it would stretch its grain into blotches. The canvas is drawn at CSS-pixel resolution, debounced 60 ms on resize and on any fader setting change, and once synchronously at boot so it is there when the cover lifts.
- **Content stamps.** `build-manifest.mjs` appends `?v=<8 hex of the file sha1>` to every clip, HEVC, poster and webm path in `items.json`, so a clip replaced under the same name gets a new address and no cache (browser or CDN) can serve the old file.
- **Clip cache.** Each clip is downloaded once into memory (a Blob) and every tile plays from that blob URL; a tile shows its poster until its clip has arrived. Browsers drop a removed video's buffer, so without this a tile leaving and re-entering the grid, or a second tile with the same clip, downloaded it again. A failed download falls back to plain streaming.
- **Scroll-time video hold.** While the grid moves fast (pan lag above 40% of the speed reference, so only a hard flick) the pool creates and starts no new videos; tiles keep their poster and videos start 60 ms after the grid calms, in bursts of 4 every 40 ms. Starting decoders mid-scroll is what dropped phones to about 22 fps.
- **Coast.** After a drag release the pan target keeps moving at the fling velocity (sampled over the last moves; a finger held still for 80 ms is no fling), decaying by `motion.coast` per frame (default 0.95, 0 to 0.99; 0 stops dead). Reduced motion turns it off. Wheel input is unaffected (the OS already adds inertia).
- **Velocity bow.** The dome bows harder the faster the grid pans: effective bow = `motion.bow` + `motion.bowVelocity` x speed, where speed is the pan lag (distance between where the pan is heading and where it is, both axes) over half the viewport's short side (450 px at 1440x900), clamped to 0..1 and smoothed at `motion.bowSmooth`. The effective bow is capped at 0.5, the `motion.bow` slider maximum, so row seams stay hidden. It works the same for drag, wheel and keyboard, eases back to the resting bow when the pan settles, and then the grid writes nothing. `bowVelocity` 0 is exactly the resting dome; reduced motion disables it with the rest of the dome.
- **Row fade.** In `fader.mode` `rows` or `both`, the headline block (title and subtitle) and the dock (pill and note) are two vertical bands, measured from the page on layout, resize, rotation and breakpoint changes, when fonts arrive or those elements change size, and one frame after a panel change that can move them (`grid.refreshZones()`), never per frame; a band that is empty or outside the viewport is ignored, and overlapping bands are fine. In the existing geometry pass each near tile's warped vertical extent is compared with each band: weight = band strength x the share of the tile's height inside the band, where the band's coverage is 1 inside and eases to 0 along a smoothstep over `fader.rowSpread` px beyond each edge (the mean of that profile over the tile height, in closed form, `rowFadeWeight` in math.js): a tile fully inside weighs the full strength, a tile half inside about half (a little more with a spread), a tile clear of the band by the spread 0, continuous and monotone in between; the weight is the max over the bands, and opacity = 1 - weight x (1 - `fader.rowOpacity`). Vertical only, so a tile's horizontal position does not matter. Opacity is written on the card host only when it moves by more than 0.01 (or back to exactly 1); parked cards get none and pick up the right value with their first write on return. An idle page still writes nothing; a band re-measure forces one geometry pass. No CSS transition (it is driven per frame); under reduced motion it applies statically. Faded tiles keep playing.
- **Dome seams.** Each tile's warped quad comes from its period box (tile plus half the gaps), so tiles in a row share warped corners exactly. Shifted rows do not share corners, so a hair-thin seam between rows (straight-edge warped quads) is accepted; it is invisible at low dome strength.
- **Video playback:** every card shows its poster first. Only cards in view play, capped at 12 concurrent videos; the rest stay on poster. Videos are `muted playsinline loop` and are paused when off-screen or when the tab is hidden. Source is attached lazily when a card first enters the padded visible area. The source is the item's HEVC file when it has one and `canPlayType('video/mp4; codecs="hvc1.1.6.L120.90"')` is non-empty (the full codec string: Chrome answers no to a bare `hvc1`), otherwise the H.264 file; an error on the HEVC file switches to H.264 once. Posters come from the H.264 file.
- **Video start recovery (exists because of Safari):** Safari does not start loading `<source>` children appended to a `preload="none"` video and reports no error (seen: every tile at readyState 0, network idle), so every attach (first attach, HEVC to H.264 fallback, re-attach after a drop or a codec override) calls `load()` once after the sources and before the first `play()`. A refused `play()` other than `AbortError` (for example `NotAllowedError`) is retried 500 ms and then 1500 ms after the refusal while the tile still wants to play: at most two retries per attach, so once they are used a later sync may call `play()` again but never starts a new retry chain; the budget resets only with a new attach or when the tile leaves view and comes back. An `AbortError` comes from our own pause, `load()` or source change and is never retried. A stall watchdog runs for each tile the pool wants playing until its video has fired `playing` (started); a tile that started and then rebuffers is never escalated, the browser handles it. It samples once a second and counts the seconds in a row without progress (progress: readyState went up, the end of the buffered range moved, currentTime moved while the network is loading, or a `progress` event reported bytes arriving, the only sign of life while the file header is still downloading); any progress resets the count, so a slow but moving download is never touched. At 3 s without progress it calls `load()` and `play()` once; at 6 s without progress the single HEVC to H.264 fallback (HEVC tiles only); at 10 s without progress it gives up: the tile drops its video, shows its poster, frees its playing slot for the next card and is marked `failed`, tried again only after it leaves view and comes back. The nudge and the fallback each happen at most once per attach, progress does not re-arm them. An error on the H.264 file (first choice, or after the fallback) is terminal: the tile gives up at once instead of holding its slot. Retries and the watchdog stop when the tile is paused, dropped or the tab is hidden, and restart with a fresh count when it resumes. The dev panel's "force load()" switch can turn the load-on-attach off for comparison; the watchdog's nudge still calls `load()`, so the switch compares "starts at once" against "starts after 3 s without progress". If the data is ready but playback never starts (`readyState >= 3`), only `play()` is retried and the tile gives up at 10 s without a reload or codec switch.
- **Reduced motion:** `prefers-reduced-motion` shows posters only, disables dome warp animation and the cursor bulge; drag/pan still works.
- **Input:** wheel, pointer drag (pointer events with `setPointerCapture`, `touch-action: pinch-zoom`, window-level move/up/cancel so touch and pen drags never abort), keyboard arrows and space. Document locked per the skill (`overflow: hidden`, `overscroll-behavior: none`, fixed body). Pinch zooms the whole page like a photo: the viewport has no zoom lock, the stage's `touch-action` leaves pinch to the browser, ctrl + wheel (a trackpad pinch) is not swallowed, and while the page is zoomed in (visualViewport scale above 1.02) the grid stops taking touch drags and `touch-action` widens to `pan-x pan-y pinch-zoom` so one finger pans the zoomed view.
- **Loading:** a full-viewport cover holds until the posters near the viewport and the two first-paint fonts have settled, all inside one 2 s cap (`POSTER_TIMEOUT_MS` in main.js), so a slow network cannot hang the reveal. A CSS-only failsafe (`cover-failsafe`, a 0.4 s fade starting at 4 s) lifts the cover even if main.js never runs; once faded the cover is `visibility: hidden`, so it stops being a composited layer.

## Dock behaviour

- Fixed overlay with its own `z-index` and `translateZ(0)` layer, above the stage. Receives pointer events; the stage underneath ignores them while over the dock.
- Copy success animation: on a successful copy (clipboard or fallback path), in addition to the toast and the live region, the Lucide `copy` icon scales and fades out while the Lucide `check` icon fades in and draws itself (stroke-dashoffset, `pathLength` 1). The check holds for `dock.iconRevertMs` (default 2000 ms), then the swap reverses. A new successful copy during the hold restarts the timer and the check stays. A failed copy never changes the icon. The swap lasts `dock.iconAnimMs` (default 280 ms). Both icons are stacked in the same fixed icon box, so the button never changes size, and in the compact filled variant only the icon swaps (the label stays). The button's accessible name does not change; the toast and the live region announce the success. Under `prefers-reduced-motion: reduce` the swap is instant (no transition) and the revert still happens after the hold. The state is the class `is-copied` on the button; the timer is cleared when the dock is destroyed.
- States: Default and Hover; Copied is the `is-copied` class on the Copy button during the icon hold (no separate dock state). Keyboard focusable with a visible focus ring; the prompt text is selectable.
- Under ~600px wide it switches to the compact variant: the visible prompt is dropped and the pill holds just the buttons, centred, with the note below. The app link no longer depends on width (a narrow desktop window keeps both buttons: filled "Install with Claude" and the icon-only Copy). Only on a non-desktop platform (`data-app="none"`, see Install flow) is the app link hidden and Copy the single filled, primary button showing the icon plus the label `copy.buttonCompact` (default "Copy install prompt": the prompt text is hidden there and Copy is the only action, so the label says what is copied; the label stays on one line and the pill sizes to its content), at any width. In that state the button's accessible name and tooltip follow the visible label (`copy.buttonCompact`, label in name), otherwise `copy.button`. A failed copy reveals the prompt as before. The app link is a plain anchor, so it never touches the grid or the Copy flow.

## Visual design

The look is decided live in the browser, in conversation, on top of a working skeleton, not in Figma. This spec fixes structure and behaviour; the values themselves are the config defaults, not fixed here.

**One config, applied as CSS variables.** All styling values live in a single defaults object (`site/js/config.js`) and are applied to `:root` as CSS custom properties at boot. Visual values come from that single object and are inlined as boot variables in `index.html` (generated by `scripts/site/sync-boot-vars.mjs`). Structure-level constants live in CSS and JS and are documented where they are: the compact breakpoint (600px, `@media` in site.css and `COMPACT_MAX_WIDTH` in math.js), the cover failsafe delay (4 s, site.css) and the cover cap (2 s, main.js). The `var()` fallbacks in site.css repeat the defaults for the no-boot-vars case, and a test pins them. Baking in your choices means editing that one object and re-running the sync script.

**Tweak panel (development only).** A hidden panel with live controls, opened with the T key. It is loaded by a dynamic import only on dev hosts (`localhost`, `127.0.0.1`, `[::1]`, tailnet addresses in 100.64.0.0/10, `*.ts.net` names and dotless machine names, decided by `site/js/devhost.js`), so it never runs on the live site; over plain http Copy settings uses its textarea fallback; it is deleted once the choices are baked in. Controls:
- **Colours:** stage, fader (`color.fader`, the stage colour so the ellipse blends in; every preset sets it equal to its stage), headline (the title line), subtitle (`color.headlineSub`, the second line), dock fill, button, button text, copy fill and copy hover (the secondary Copy button; `color.secondaryFill` and `color.secondaryHover`, plain colour fields that accept rgba), text, muted text, toast fill, toast text.
- **Grid:** tile size, gap, row gap, corner radius, minimum columns, columns phone (minimum columns up to 600px wide); aspect (square or native) with the native clamp (aspect min, aspect max); row shift with its shift mode (alternate, step or random); row speed (parallax); a Reshuffle button that deals a new seeded order.
- **Motion:** dome strength (at rest), bow velocity (extra dome at full pan speed) and bow smoothing (how fast it follows and eases back), cursor bulge and reach, drag glide, vignette, flashlight shade and edge.
- **Shadow and glass:** card shadow (strength, blur; cards only), dock blur, dock fill opacity, border brightness.
- **Dock:** corner radius, gap (prompt to buttons), padding, cta gap (between Install with Claude and Copy), cta pad (padding around the two buttons), its own shadow (strength, blur), check hold ms (`dock.iconRevertMs`, default 2000, 500 to 6000 in steps of 100) and icon anim ms (`dock.iconAnimMs`, default 280, 100 to 800 in steps of 20); `iconAnimMs` is emitted as a CSS variable in ms; `iconRevertMs` is read by dock.js only.
- **Headline (title line):** size (default 65 px, 24 to 400) and compact size (default 43 px, 16 to 160), both fixed px, never viewport-relative, weight (default 500, 200 to 900 in steps of 50: Source Sans 3 is bundled as a variable font, so every step renders), tracking (em), line height (default 0.8), gap above the dock and gap above the dock on phones (px between the block's bottom edge and the dock's top; defaults 18 and 12, 0 to 200; they replace the old distance-from-bottom offsets `headline.bottom` and `headline.bottomCompact` and the older `headline.y`, and stored values for those are dropped, not reinterpreted), opacity, shadow strength (default 0, off; a tight plus a wide soft shadow in the stage colour for legibility over moving clips), line gap (em of the title size, 0 to 1, default 0.12, the space between the two lines) and ligatures (0/1, default 1: forces `liga` and `clig` on or off for both lines; Safari behaviour with tight tracking is unverified). Stored values are clamped through the same ranges as the sliders: size 3 to 20 vw, compact size 4 to 24 vw, weight 200 to 900, tracking -0.08 to 0.1 em, line height 0.8 to 1.4, bottom and bottom phones 0 to 800, opacity 0 to 1, shadow 0 to 1.
- **Fader:** opacity (default 1, 0 to 1 in steps of 0.05; 0 hides it), width (px, default 4260, 200 to 8000, fixed) and height (px, default 1510, 100 to 4000, fixed), each with a phone pair (780 and 510), offset (px, default -382, -1600 to 1600 in steps of 2: the ellipse CENTRE sits this far above the viewport bottom,; a negative value sinks it below the screen edge) and softness (default 0.18, 0 to 1: the solid fraction before the feather; 0 is feathered from the centre, 1 a hard edge). Mode (segmented: ellipse, rows, both, off; default ellipse) heads the group; after the ellipse sliders a short note introduces the row-fade sliders: rows (`fader.rowOpacity`, default 0.5, 0 to 1 in steps of 0.05: opacity of tiles fully behind a band), spread px (`fader.rowSpread`, default 40, 0 to 600 in steps of 5: the feather beyond the headline and dock; 0 is a hard band), headline and dock strengths (default 1, 0 to 1 in steps of 0.05). These five keys are read by JavaScript only and are never CSS variables. Its panel group follows Subline, with the fader colour in the Colours list; stored values are clamped through the same ranges.
- **Subline (subtitle line):** size (default 26 px, 10 to 120) and compact size (17 px, 8 to 60), fixed px, weight (400, 200 to 900 in steps of 50), tracking (0 em, -0.08 to 0.2), line height (1.25, 0.85 to 1.8 in steps of 0.05), opacity (0.9) and shadow strength (default 0). It inherits the title's ligatures switch. Both groups follow Type in the panel; each slider has a short label and help text, and the two colours (`color.headline`, default #E0E0E0, and `color.headlineSub`, default #AAAAAA) sit in the Colours list. The wording is two fields in the Copy group (`copy.headlineTitle` "Gaffer" and `copy.headlineSub` "your AI crew in After Effects", at most 80 characters each, textContent only, live); the earlier single `copy.headline` is gone and a stored one is ignored.
- **Code ligatures:** `type.codeLigatures` (0/1, default 1) in the Type group turns the prompt font's ligatures on or off (`calt` and `liga`); only JetBrains Mono has any (such as `//`), Source Code Pro has none.
- **Toast:** the default is a light pill with dark text (`color.toastFill` #E0E0E0, `color.toastText` #121212); the Warm graphite, Paper and Gaffer panel presets each keep their own contrasting pair. Corner radius, shadow strength, blur and offset, duration; a Show toast button previews it.
- **Type:** UI and prompt fonts, each a list of stacks (bundled: Source Sans 3, Source Code Pro, JetBrains Mono; the rest are system fonts) plus a free-text font-family field; base size, prompt size, weight (200 to 900) and prompt weight (`type.monoWeight`, default 400, 100 to 800 in steps of 50, unitless `--type-mono-weight` on `.dock-prompt`; JetBrains Mono is variable, other mono fonts use the nearest weight).
- **Copy:** the app button label, the Copy button's accessible name and tooltip, and its compact label, the success and failure toast messages. Plain text only, at most 80 characters; never a CSS variable.

Sliders are custom, pointer-driven controls (not native range inputs), so they work with a pen. Changes apply instantly and persist in `localStorage` while experimenting. **Copy settings** exports the current values as JSON, which is how choices come back to be baked into the defaults.

**Presets.** Four one-click starting looks to compare, each just a set of values for the same controls: *Night glass* (near-black stage, glass dock), *Warm graphite* (softer, warmer dark), *Paper* (a light stage, for contrast) and *Gaffer panel* (the panel's own palette and fonts). The panel can switch between them and tweak from any of them.

Source Sans 3 (variable upright, `SourceSans3VF-Upright.otf.woff2`, wght 200 to 900, one `@font-face`), JetBrains Mono (variable upright, `JetBrainsMono-VF.woff2` converted from the official variable TTF with all glyphs and features kept, wght 100 to 800, one `@font-face`) and Source Code Pro (single weight, `SourceCodePro-Regular.woff2`), all SIL OFL, are bundled in `site/fonts/` with their licences; no italics are bundled; the final choice is made in the styling pass. The toast, and any dock "Copied" state, are styled in the same pass.

## Page basics

- `<title>` and meta description, Open Graph tags; OG image is the poster of the first item. Exactly one `<h1>`, the visible headline: two spans, the title and the subtitle (static text, `copy.headlineTitle` and `copy.headlineSub`), separated by a visually hidden ", " so assistive technology reads one phrase. Grid videos are decorative (`aria-hidden`), and so is the fader (an empty `<div class="fader" aria-hidden="true">` after the stage, outside it).
- First paint: the cover is opaque from the first paint. The default config variables are inlined in a `<style id="boot-vars">` block in the head, before the stylesheet, so nothing depends on main.js to be styled; the block is generated from `configToCssVars(defaults)` and a test fails when it drifts (after changing config defaults run `node scripts/site/sync-boot-vars.mjs`). `html`, `body` and `#cover` also carry literal `#121212` fallbacks, with `color-scheme` and `theme-color` metas. Source Sans 3 and JetBrains Mono are preloaded, use `font-display: block`, and gate the cover lift (`document.fonts.load`, together with the grid) inside the same 2 s cap, so a hung font never holds the cover. With `font-display: block` text can stay invisible for up to about 3 s when a font arrives after the 2 s cap (an accepted trade-off). A 4 s CSS failsafe on the cover covers the case where main.js never runs.
- No-JS: the cover is hidden, and the headline, dock and note render statically with the real defaults (the boot variables); a short message says the gallery needs JavaScript; the grid does not render. The noscript block holds only the cover rule, the app-link underline and the phone layout that wraps the prompt.
- Tile media is hidden from browser extensions. Each card's poster and video live inside a closed shadow root on the card, so a page scan (`querySelectorAll('img, video')`, a MutationObserver on the document, `elementsFromPoint`) finds no tile image or video, and events from inside report the card. The page keeps its own references to the media; their styles are one shared constructable stylesheet adopted by every root (an inline `<style>` per root where that is unsupported). Tile media also ignores the pointer (`pointer-events: none`, no drag, no picture-in-picture or cast), and the stage disables its context menu. The dock, toast and tweak panel keep their normal menus.
- Honest limit: this stops extensions that scan the page for images and videos or hook hover (Savee, Pinterest style "Save" buttons). An extension that targets this page on purpose can still open closed shadow roots (`chrome.dom.openOrClosedShadowRoot`, or wrapping `attachShadow` before the page script runs). It is not copy protection: screen capture, the network tab, direct file URLs, and extensions that screenshot the page or read its pixels still work. Whether a given extension (Savee, Pinterest) is actually stopped can only be confirmed in the user's own browser with that extension installed.
- No analytics, cookies, or third-party requests. Fonts self-hosted from `site/`.

## Testing

- **`build-manifest.mjs`:** Node test for ordering, output shape, generating a poster when none exists, a hand-made poster winning over a generated one, and the HEVC companion (listed on its clip, never an item of its own, unsafe names copied).
- **Test files** in `scripts/site/`, run with `node --test scripts/site/`: `config.test.mjs` (defaults, CSS variable emission and units, JS-only keys), `dock.test.mjs` (dock markup, copy flow, icon animation, headline and CSS rules), `firstpaint.test.mjs` (boot-vars sync, cover and failsafe, noscript, fonts, `var()` fallbacks), `fonts.test.mjs`, `serve.test.mjs` (Range server), `media.test.mjs` (tile media, video start recovery and the stall watchdog), `math.test.mjs` (grid math: wrap, warp, homography for non-square tiles, row rings, row shift and parallax, native aspect clamp, velocity bow, row fade weight and opacity), `grid.test.mjs` (row fade targets and card writes), `build-manifest.test.mjs`; `tweak.test.mjs` and `devhost.test.mjs` are dev-only and go with the panel. `node scripts/site/sync-boot-vars.mjs --check` fails when the boot-vars block drifts.
- **`build-manifest.mjs`** tests cover ordering, output shape, generating a poster when none exists, a hand-made poster winning over a generated one, and the HEVC companion (listed on its clip, never an item of its own, unsafe names copied).
- **Browser checks** at 1440x900, 768x1024 and 390x844: no pop on wrap with 3 items and with 40, in square and native mode with row shift and parallax, no card hover state, drag with mouse and touch emulation, dock states, reduced-motion, video concurrency cap, copy fallback.
- **Pen/stylus drag** can only be confirmed on a real device; flagged as a manual check.
- **Local preview:** use `node scripts/site/serve.mjs` (options `--dir`, `--port`, `--bind`), not `python3 -m http.server`: Safari needs `206 Partial Content` range responses to play video, and Python's server answers ranges with a plain 200. GitHub Pages supports ranges, so this only affects local previews.
